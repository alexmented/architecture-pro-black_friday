# Задание 7

## Схема

@startuml

entity products {
+ _id          : int <<PK>>
  --
  name          : String
  category      : String
  price         : Double
  stock         : Object
  attributes    : Object
  }

entity orders {
+ _id          : int <<PK>>
  --
  client_id     : ObjectId <<FK>>
  created_at    : DateTime
  productIds    : Array<int> <<FK>>
  status        : String
  total_amount  : Double
  geo_zone      : String
  }

entity carts {
+ _id          : int <<PK>>
  --
  user_id       : int <<FK>>
  session_id    : String
  productIds    : Array<int> <<FK>>
  status        : String
  created_at    : DateTime
  updated_at    : DateTime
  expires_at    : DateTime
  }

orders }o--|| products : "productIds → _id"
carts  }o--|| products : "productIds → _id"
@enduml


## Кандидаты на шард-ключи
orders

client_id - работа с клиентами

productIds - ранжирование по количеству товаров

geo_zone — шардирование по геолокации

_id (hashed) — равномерное распределение

products

_id (hashed) — равномерное распределение

category (range) — выборка по разделам

carts

id (hashed) — равномерное распределение
user_id (hashed) - для авторизованных юзеров

## Стратегия шардиования
orders
- client_id - для работы с заказом клиента на одном шарде

products
- id - гарантирует равномерное распределение, тк разделение по категориям может вызвать сильный перевес в какой-то из категорий

carts
- id = равномерное распределение, тк не все юзеры могут быть авторизованы и гостевых юзеров может быть больше авторизованных

1. Инициализация config-сервера

```shell
docker compose exec -T configSrv mongosh --port 27017 --quiet <<EOF
rs.initiate(
  {
    _id: "config_server",
    configsvr: true,
    members: [
      { _id: 0, host: "configSrv:27017" }
    ]
  }
);
EOF
```
2. Инициализация шардов
```shell
docker compose exec -T shard1 mongosh --port 27018 --quiet <<EOF
rs.initiate(
  {
    _id: "shard1",
    members: [
      { _id: 0, host: "shard1:27018" }
    ]
  }
);
EOF

docker compose exec -T shard2 mongosh --port 27019 --quiet <<EOF
rs.initiate(
  {
    _id: "shard2",
    members: [
      { _id: 0, host: "shard2:27019" }
    ]
  }
);
EOF
```

3. Добавление коллекций
```shell
docker compose exec -T mongos_router mongosh --port 27020 --quiet <<EOF
sh.addShard("shard1/shard1:27018");
sh.addShard("shard2/shard2:27019");
sh.enableSharding("black_friday");

// orders по client_id
sh.shardCollection("black_friday.orders", { "client_id": "hashed" });

// products по _id
sh.shardCollection("black_friday.products", { "_id": "hashed" });

// carts по _id
sh.shardCollection("black_friday.carts",   { "_id": "hashed" });
EOF
```

# Задание 10
Выделим архивные записи по статусам из orders и carts. Они не являются критичными и их можно перенести в Cassandra
Для критичных данных используем MongoDb + Redis
Опишем создание таблиц

```shell
CREATE TABLE IF NOT EXISTS orders (
    id UUID,
    client_id UUID,
    productIds LIST<text>,
    created_at timestamp,
    status text,
    total_amount decimal,
    geo_zone text,
    PRIMARY KEY ((client_id), created_at, id)
) WITH CLUSTERING ORDER BY (created_at DESC, id DESC);
```
Partition key: client_id
Cluster keys: created_at, id
Обоснование:
Все заказы одного клиента хранятся на одном узле
Хранение по времени создания и ускорения доступа к более новым заказам

```shell
CREATE TABLE IF NOT EXISTS carts (
    id UUID,
    user_id UUID,
    session_id UUID,
    items map<text, int>,
    status text,
    created_at timestamp,
    updated_at timestamp,
    expires_at timestamp,
    PRIMARY KEY ((user_id), updated_at)
)
```
Partition key: user_id
Clustering keys: updated_at
Обоснование:
Все корзины пользователя на одном узле
Хранение по дате обновления

Для обеспечения целостности данных следует использвать:
- Hinted Handoff - применить к carts и orders для решения проблем с консистентностью при кратковременных сбоях
```shell
hinted_handoff_enabled: true
# Окно хранения подсказок
max_hint_window_in_ms: 10800000
# Директория для хранения подсказок
hints_directory: /var/lib/cassandra/hints
```
- Anti-Entropy Repair - включить, чтобы была консистентность при долговременных сбоях
